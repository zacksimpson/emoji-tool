# Emojis — Claude Context

Light Phone III app for browsing, searching, and copying emojis. Built with Expo / React Native, targeting Android only.

## Stack

- Expo 55, React Native 0.83, expo-router (file-based routing)
- TypeScript, bun as package manager
- EAS CLI for cloud builds / OTA updates
- Android package: `com.zack.emojis`

## Key conventions

- **`n(value)` for all dimensions** — scaling utility in `utils/scaling.ts`, normalizes to Light Phone III pixel density. Never use raw pixel values.
- **No gray colors, no dividers** — Light Phone design language is strictly black/white.
- **No comments** unless the why is non-obvious.

## Project structure

- `app/` — expo-router routes
  - `(tabs)/` — tab navigator (index, search, topused, settings)
  - `confirm.tsx` — emoji copy confirmation screen
  - `settings/sort-frequents.tsx` — sort order for frequent emojis
- `components/` — shared UI (Header, Navbar, HapticPressable, TextInput, ToggleSwitch, StyledText, SwipeBackContainer)
- `utils/` — emojiData.ts, haptics.ts, scaling.ts
- `contexts/` — React context providers
- `plugins/withDebugApplicationIdSuffix.js` — allows debug + prod APKs to coexist on device

## Dev workflow

```bash
bun install          # install deps
bun run dev          # expo run:android — builds and installs debug APK on connected device
```

Debug APK installs as `com.zack.emojis.debug` (separate from production via the suffix plugin).

## Build / release

```bash
eas build --platform android --profile production   # cloud build → APK distributed via Obtainium
eas update                                           # OTA update (no new APK needed)
```

Do **not** push `v*` git tags unless intentionally triggering an EAS build — it costs credits.

## Android environment (Mac)

- Java: OpenJDK 17 at `/opt/homebrew/opt/openjdk@17`
- Android SDK: `~/Library/Android/sdk`
- Both are in `~/.zshrc`; non-interactive shells need `JAVA_HOME` set explicitly
- `android/` is not tracked in git — regenerated by `expo prebuild`
